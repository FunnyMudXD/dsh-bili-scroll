# 这个 fork 改了什么（相对上游 `c1overzz/dsh-bili-scroll`）

> 基线：**上游 0.1.7**（npm 上能装到的那版），再往上加/修了下面这些。
> 每条都按「现象 → 根因 → 改法 → 怎么验」写，方便以后自己回看，也方便想抄的人。
> 上游 0.1.9–0.1.12 的修复已经合并进来（见最后一节）。

---

## 一、面板：从「设置页」搬到「侧栏」

- **现象**：设置页里那一大坨用法很别扭 —— 想看日志得来回切，跑起来的时候看不到进度。
- **改法**：
  - 注册成**侧栏面板**（`slots.inject('main')` + `slots.inject('sidebar.panellist')`，`order=40`，排在记忆系统后面）
  - **页头置顶**：标题 / 状态胶囊 / 总开关 / 「现在跑一轮」固定不动，下面的卡片区自己滚
  - **实时日志**块固定在上半区：跑着时 1.5 秒刷、空闲 6 秒，只取 `duty.log` 尾部 300 行（文件大了只读最后 160KB，并丢掉截断点那半行）
  - 卡片区用 `column-count:2` 的瀑布流
  - **服务总开关**（页头那个绿/红灯）：关掉 = 定时器不跑、手动「跑一轮」被拒、发评论被拒；只保留读状态与改设置（不然关了就再也打不开）
  - 侧栏图标右下角有一盏灯，跟着总开关变绿 / 变红
- **坑**：面板宿主区是 `display:flex;flex-direction:column;overflow:hidden` ⇒ 面板必须**自己滚**（`height:100%` + `overflow-y:auto`），否则下半截被裁掉。

## 二、配置

| 改动 | 说明 |
|---|---|
| **可改「地盘」**（数据目录） | 设置里填绝对路径就搬家：凭证 / 报告 / 日志 / 判重表复制过去（老家不删），后续读写全落新家。⚠️ **venv 不搬**（Windows 的 venv 里钉着绝对路径，搬过去跑不了），换完点一次「装主依赖」重建 |
| **多 @** | `mentionNames`（数组）优先，老的单个 `mentionName` 兜底；正文里每个人单独写一次 `@昵称` |
| **这一轮用哪个模型** | `modelProvider` + `modelName`，两个都填才生效；空 = 跟 profile 默认 |
| **单轮 / 全天额度拆开** | `perRound`（一轮最多挑几条，0 = 不限）+ `perDay`（全天总量）—— 自动轮频繁跑时用前者控节奏 |

## 三、跑一轮

### 3.1 连点就起好几轮
- **改法**：`dutyRun` 单飞锁 —— 上一轮还在跑时，第二次点直接回「上一轮还在跑（已经 N 秒）」。
- **另**：定时器回调里抛的异常必须接住（`setInterval(tick).catch(...)`）—— 第一版没接，一次 TypeError 把整个宿主带走了。

### 3.2 提示词太长 / cmd.exe 引号
- **改法**：任务走 **stdin**（`dsh --profile headless --patch <overlay> -`），不把几千字塞进命令行；`dshSpawn` 统一处理 `.cmd` 与带空格的路径（`windowsVerbatimArguments`）。

### 3.3 找不到 dsh
- **现象**：桌面版是 Electron 安装包，不是 `npm -g` 装的 ⇒ 猜的位置全找不到 ⇒ 那一轮必然失败，日志只有一句 `code=1` 和一段乱码。
- **改法**：`resolveDsh()` 认桌面版的真正入口 `<resources>/runtime/cli/bin/dsh.cmd`；**找不到就停下说清楚**（"去设置里把 dsh 路径指过去"）+ 补一份占位报告，不再硬 spawn 一个不存在的 `dsh`。

### 3.4 `NO_ADAPTER: no adapter registered for provider "ark"`
- **根因**：用户在「设置 → 模型」里加的供应商只写进**桌面 profile 的 `cordis.patch.yml`**（`- id: llm-pi-ai`），而跑一轮用的是 **headless profile** —— 那边没有这段，自然没有那条路由。
- **改法**：`piAiBlock()` 去 profile 目录里把 `- id: llm-pi-ai` 那一段**原样搬进 overlay**；只要选的 provider 不在 base 里就搬（不针对某个厂商写死）。
- **验证**：用真实配置拼 overlay 跑 headless，`provider=ark` 那轮 exit 0。

### 3.5 `MISSING_CREDENTIAL: deepseek-official`
- **两个原因**：① headless 从没给 base provider 打开 `credentials`；② 凭据库里那把是 `ark-…` 不是 `sk-…`。
- **改法**：Key 状态检查（`deepseekKeyState()`）+ 开跑前早拦 + 页面标「缺 Key」；overlay 里对有 Key 的情况打开 `credentials`。

### 3.6 一轮白跑（`reasoning_content must be passed back`）
- **根因**：思考型模型（`deepseek-v4.1-flash-free`）在这个协议下不支持多轮工具调用。
- **改法**：`explainDeath()` 把 `reasoning_content` / `ModelNotOpen` / `NO_ADAPTER` / `MISSING_CREDENTIAL` 翻成人话写进日志，别只留一句 code=1。

## 四、评论复核（修两个真 bug）

- **现象**：点「复核」时，明明发出去的评论报「没查到」。
- **根因 ①**：判重表解析把**整行所有长数字**都当候选 —— 第一个当 rpid、第二个当 root。于是备注里随口提到的另一个 id 被当成 root ⇒ 去查那一串楼中楼当然查不到。
- **根因 ②**：顶层只查「最新一页 20 条」；视频一活跃，自己那条被挤到第 2 页 ⇒ 误判。
- **改法**：表格行**按列取**（第 2 列 rpid、第 3 列 root），非表格行才退回扫数字；加常识校验 `root >= rpid` 视为记错、按顶层查；顶层按 `cursor.next`、楼中楼按 `pn` **各最多翻 3 页**。
- **验证**：实测那条从「没查到」变成「公开可见（赞 13）· 顶层·第 2 页」。

## 五、回复：窗口内全量扫 + 规则打分

- **原来**：让模型自己在判重表里挑最近 5~8 条评论，再去热门评论 / 楼中楼里找 —— 翻页翻不到、每轮白扫、还漏人。
- **现在**：
  1. 宿主按 `replyLookbackDays`（默认 7 天）把自己发过的评论**全量扫一遍**
  2. 每条拉 `/x/v2/reply/reply?root=` 拿回复（按 root 去重，同一串只查一次）
  3. 跳过自己的、跳过已回过的（`replied.jsonl` 记 `(root, source)`）
  4. **规则打分**，≥ `replyMinScore`（默认 3）才进清单
  5. 模型只负责写正文并通过 `bili_reply`（带 `rpid` / `root`）发出去
- **打分表**：

  | 规则 | 分 |
  |---|---|
  | 像提问（`？`/怎么/为什么/在哪/能不能/求/如何/吗/咋/是吧/还是/不$/没$） | +3 |
  | 提到本插件 / 这一轮（插件/刷B站/大肥鱼/主人/报告/三连） | +2 |
  | 轻互动（谢谢/厉害/哈哈/可爱/笑死） | +1 |
  | 带联系方式或外链 | −5 |
  | 明显敌意 | −5 |
  | 超长（>200 字） | −3 |
  | 纯表情 / 标点 | −2 |

- **三个踩过的坑**：
  - 口语问句没问号（"会自动重连不，还是得手动重启"）被漏 ⇒ 问句正则补上口语形态
  - 判重表里「我们那条顶层评论」和「我们那条回复」指向**同一个 root** ⇒ 同一串查两遍、同一个人列两次
  - 模型是**直接调 MCP 的 `bili_reply`**，走不到宿主工具 ⇒ `replied.jsonl` 一直是空的、下一轮会重复回。现在 MCP 里回完自己记一笔。

## 六、顺手三连

- **开关 + 独立日上限**（默认关、默认 5 条、0 = 不三连、默认 1 枚币）；只给「这一轮挑中、要发评论」的那几条。
- **收藏夹**：官方一键三连（`/x/web-interface/archive/like/triple`）**只能进默认收藏夹** —— 指定了具体收藏夹就自动改走分步 `like → pay_coin → /x/v3/fav/resource/deal`。
- **闸门下发给那一轮**：`BILI_TRIPLE` / `_LEFT` / `_COIN` / `_FAV` / `_STATE` 由宿主写进 overlay 的 MCP env —— 开关、额度、币数、收藏夹、记账文件**全由宿主决定，模型改不了**。
- **话术一致性**：只有三项都成功才允许在「主人」后面加一句（多句轮换），任一失败一个字都不提。
- **记账**：`<家>/interacted.jsonl`，同一视频只花一次钱。

## 七、只评论娱乐视频

- **判断顺序**：标签白名单（命中就放行）→ 标签黑名单（命中就不评）→ **分区**（知识/科技/校园学习/职业职场/科学科普/计算机/软件应用/数码 = 技术；动画/搞笑/鬼畜/游戏/生活/美食/动物/娱乐/影视 = 娱乐）→ 标题 + 标签关键词 → **拿不准就放行**。
- **两道硬闸**：`bili_reply`（顶层评论命中 tech 直接拒）与 `bili_interact`（命中 tech 不三连）。
- **取不到视频信息 ⇒ 放行**，不因为一次接口失败卡死整轮。

## 九、已知取舍（没做的）

- **「立刻自动回」**：没做 —— 每来一条就起一次模型，成本和风控都不可控。现在只做「发现 + 打分 + 排队」。
- **监听**（消息中心 `/x/msgfeed/reply`）：没做，还在设计阶段。它比"翻评论"准得多，是下一步。
- **侧栏面板 vs 上游的设置页**：两套架构，所以本仓库的 UI 改动没法直接提给上游。
